# lore_effect —— 按装备 Lore 给药水效果（XiYing定制版）

## 关于作者

作者：xxhh.

这是一个按装备 Lore 给予药水效果的 LiteLoaderBDS（LSE QuickJS）插件。

- **生效位置**：主手 / 副手 / 盔甲栏（背包、箱子里的不算）
- **脱下立刻撤销**，切快捷栏最多 1 秒延迟（背包切换不触发事件，只能轮询兜底）
- **不抢药水**：玩家身上已有的同名效果，本插件不去覆盖，等它自己掉了才接管
- 控制台横幅、`/lorefx` 状态页都带 **XiYing定制版 v1.2.0**（版本号读 `manifest.json`）

## 装法

把整个 `lore_effect` 文件夹丢进服务器 `plugins/` 目录，重启（或 `ll reload lore_effect`）。
首次启动会生成 `config/lore_effect/config.json`。

依赖：LeviLamina + `legacy-script-engine-quickjs`（manifest 里已声明）。

> 文件夹名 `lore_effect` 是写死的（`require("plugins/lore_effect/...")`）。
> 想改名就把 `index.js` + `src/*.js` 里的这几处 require 前缀一起换掉。

## Lore 怎么写

一行写一个效果，**必须跟等级**（数字或罗马数字都可以）；同一行可以写多个，空格/逗号随你。

| 写法 | 结果 |
| --- | --- |
| `速度II` / `速度 II` | 速度 二级 |
| `速度2级` / `速度 等级2` / `速度 Lv.2` | 速度 二级 |
| `力量+2` / `力量 提升 2` | 力量 二级 |
| `急迫+1` / `急迫I` / `挖掘加速+1` | 急迫 一级 |
| `抗性提升IV 生命恢复I` | 抗性提升 IV + 生命恢复 I |
| `speed2` / `strength:2` | 英文 id 也认 |
| ~~`速度`~~ | **不生效**（1.0.3 起：只写效果名不算，必须跟等级） |
| `§c速度§r§l II` | 带颜色码没关系，会先剥掉 |

**故意不认的写法**：

- `攻击速度+10%` —— 百分号说明这是在写属性数值，不是药水效果。不挡的话全服装备的
  「攻击速度」条目都会变成速度药水。
- 含 `上限` / `概率` / `几率` 的整行（默认黑名单，配置可改）。

完整关键词表：游戏内 `/lorefx list`（30 个效果，中文名 + 英文 id + 别名都认）。

## 时长与挂法：视觉类挂「无限」，没有倒计时就不会闪

夜视、失明、反胃、黑暗、潮涌能量这类效果在**快到期时**客户端会做亮度或画面过渡
（夜视最明显：到期前约 1 秒亮度开始回落）。只要时长会走到 0，就会闪。

**所以视觉类默认直接挂无限时长**（`visual_mode: "infinite"`）：HUD 上没有倒计时，
永远走不到那段过渡，脱下装备时再移除。

> 为什么不是「挂 15 秒然后续期」？因为**对已存在的同等级效果再 `addEffect` 在部分 BDS
> 版本上是空操作，不会延长时长**。线上现象正是「15 秒倒计时跑完 → 再重挂」，看着像循环。
> v1.0.1 就是踩了这个坑。v1.0.2 起：视觉类无限，其余效果续期改成**先删再挂**（保证计时器真的重置）。

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `visual_mode` | `"infinite"` | 视觉类挂法：`infinite` 无限 / `refresh` 有限时长+续期 |
| `visual_ticks` | `300`（15 秒） | 只在 `refresh` 模式下生效 |
| `visual_min_ticks` | `200`（10 秒） | 绝对下限，**代码里硬挡 10 秒，配置只能往上调、调不低** |
| `visual_effects` | `[9,15,16,26,30]` | 反胃 / 失明 / 夜视 / 潮涌能量 / 黑暗 |
| `grant_ticks` | `400`（20 秒） | 普通效果的时长 |
| `refresh_ahead_ms` | `3000` | 普通效果提前 3 秒续期（先删再挂） |

引擎要是不吃无限时长，插件会自己发现（`addEffect` 返回 false，或挂上 1.5 秒内就被丢掉），
打一条日志并自动回落到 `refresh` 模式 —— 不需要你手动改配置。`/lorefx diag` 里能直接看到
当前是哪种模式。

## 命令

| 命令 | 谁能用 | 作用 |
| --- | --- | --- |
| `/lorefx` | 所有人 | 看自己每个槽位解析到什么、本插件挂了什么、当前时长设置 |
| `/lorefx diag` | OP | **排障用**：解析结果 / 已挂列表（几秒前挂的）/ 授予撤销计数 / `getAllEffects` 实际返回 |
| `/lorefx list` | 所有人 | 关键词表（含数字 id） |
| `/lorefx test <关键词>` | OP | 挂一个短效果，用来校准等级语义 |
| `/lorefx reload` | OP | 重载配置并重启轮询 |

出问题时把 `/lorefx diag` 的五行发我，能一句话判断是「没解析到 / 没挂上 / 被引擎丢掉 / 反复撤销」。

## ⚠ 第一次上线先做这一步：校准等级语义

LSE 文档只写了 `addEffect(id, tick, level)`，没说 `level` 是 0 起还是 1 起，不同版本
表现可能不一样。本插件默认按「写 II → 传 level 1」处理，但**必须现场确认一次**：

1. 戴一件 lore 写着 `速度II` 的装备；
2. 看左下角显示的是 **I** 还是 **II**：
   - 显示 **II** → 正确，什么都不用改；
   - 显示 **III**（高了一级）→ 把 `amplifier_offset` 改成 `-1`；
   - 显示 **I**（低了一级）→ 改成 `1`；
3. `/lorefx reload`，再戴上复看。

不想做装备也行：`/lorefx test 速度` 会挂一个短效果，直接看显示几级。

## 配置（`config/lore_effect/config.json`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `slots` | `["mainhand","offhand","armor"]` | 生效槽位，可去掉副手等 |
| `scan_interval_ms` | `1000` | 轮询间隔；`<=0` 表示只靠事件 |
| `grant_ticks` | `400` | 普通效果时长（20 刻 = 1 秒，400 = 20 秒）；`-1` = 永久 |
| `refresh_ahead_ms` | `3000` | 提前多少毫秒续期 |
| `visual_mode` | `"infinite"` | 视觉类挂法：无限 / `refresh` 有限+续期 |
| `visual_ticks` | `300` | 只在 `refresh` 模式下生效（15 秒） |
| `visual_min_ticks` | `200` | 视觉类绝对下限（10 秒，改不低） |
| `visual_effects` | `[9,15,16,26,30]` | 哪些效果算视觉类 |
| `show_particles` | `false` | 是否显示药水粒子 |
| `max_level` | `10` | 等级封顶 |
| `amplifier_offset` | `0` | 等级语义校准，见上一节 |
| `stack` | `"max"` | 多件给同一效果：`max` 取最高 / `sum` 相加后封顶 |
| `skip_instant` | `true` | 跳过瞬间治疗/瞬间伤害（每轮续期会无限刷血/掉血） |
| `require_level` | `true` | 关键词后面必须跟等级；设 `false` 恢复「不写等级按 I 级」的旧行为 |
| `trust_effect_list` | `true` | 是否相信 `getAllEffects`；某些版本返回值不可靠时设 `false`，改成纯定时驱动 |
| `blacklist_line_words` | `["上限","概率","几率"]` | 命中任一词的整行不解析 |
| `require_marker` | `""` | 只解析含该符号的行，如填 `⬥` 就只认 `⬥ 速度II` |
| `log_changes` | `false` | 每次授予/撤销写一条日志（调试期开） |
| `debug` | `false` | 打印解析明细 |

> `grant_ticks` 为什么不用 `-1`（永久）：插件被卸载 / 崩了以后永久效果会一直粘在玩家身上，
> 没人能撤。用「有限时长 + 到点前续期」，最坏情况只是多挂 20 秒自己掉。
> 代价是 HUD 上能看到 20 秒倒计时反复重置，属正常现象。

## 已知边界

1. **同名药水会被续期刷回 lore 等级**：本插件不抢玩家身上已有的效果，但一旦效果是本插件
   挂的，每 17 秒（20 秒 - 3 秒）续期一次就会把它拉回 lore 的等级（喝高阶速度药水会被拉回 II）。
   想减少干扰就把 `grant_ticks` 调大（比如 `1200` = 60 秒），续期自然变稀。
2. 粒子默认关，避免一群玩家身上冒烟。
3. 卸载插件后已挂效果最多 20 秒自己掉；**视觉类的无限效果不会自己掉**（重载/卸载前建议先脱下装备，或让玩家重新穿一次）。
4. `/lorefx` 是 `PermType.Any`（看自己状态本来就该人人可用），`reload`/`test` 在回调里查 OP。

## 离线自测

不需要 BDS，只要 Node（18+）：

```
node test/offline-test.js
```

75 项断言：解析器的各种写法、授予/撤销、不抢药水、max/sum 叠加、瞬间效果跳过、
黑名单、等级变化重挂、`amplifier_offset` 校准、`require_marker`、牛奶后自动补挂、
副手/盔甲生效、槽位配置，以及**视觉类时长下限**（含「就算 grant_ticks=100 也 > 15 秒」）
和品牌/版本号。

改完 `src/parse.js` 或 `src/runtime.js` 先跑这个再上服。

## 更新日志

### 1.0.3
- **必须带等级**：只写「力量」「速度」不再生效，必须写「力量II」「力量2级」「力量+2」「力量 等级2」。
  避免装备 lore 里随便出现一个效果名就误触发 buff（所有效果统一这条规则）。
- 新增 `require_level`（默认 `true`）；设 `false` 可恢复「不写等级按 I 级」的旧行为。

### 1.0.2
- **修「夜视 15 秒倒计时跑完再重挂」**：根因是「对已存在的同等级效果再 `addEffect`」在部分 BDS
  版本上不延长时长。视觉类改为**直接挂无限时长**（`visual_mode: "infinite"`），HUD 无倒计时、
  走不到到期过渡，不再依赖续期。
- 引擎不接受无限时长时自动回落：`addEffect` 返回 false、或连续两次挂上后读不到 → 打日志并改用
  15 秒续期模式，不需要手改配置。
- 所有有限时长效果的续期改成**先删再挂**，保证计时器真的重置（之前可能根本没延长）。
- 「效果丢失」判定加了 2 秒冷却；新增 `trust_effect_list` 开关，应对 `getAllEffects` 不可靠的版本。
- 新增 `/lorefx diag`（OP）：解析结果 / 已挂列表（含挂上多久）/ 授予撤销计数 / `getAllEffects` 实际返回。

### 1.0.1
- 视觉类效果（夜视 / 失明 / 反胃 / 潮涌能量 / 黑暗）锁定时长，不再跟 `grant_ticks` 走
- 视觉类新增 **10 秒代码级硬下限**：`visual_ticks` 写低于 200 刻会被抬回 200，`visual_min_ticks` 也只能往上调
- 续期节拍改为按**每个效果自己的时长**算（之前按全局值狂续）
- 修复：`visual_min_ticks` 被写成很小值时护栏失效（自测抓到的）
- 品牌标签 **XiYing定制版**（控制台横幅 / `/lorefx` 状态页 / `manifest.json` 描述）

### 1.0.0
- 首版：装备 lore → 药水效果，主手 / 副手 / 盔甲栏，脱下即撤销
